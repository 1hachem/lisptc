Check Before Eval

The lisp the agent writes is formatted and checked before it runs. A clean step is stored and evaluated. A step with errors goes back to the agent, which repairs it with a string edit or rewrites it.

The step, end to end

One new stage between the reply and the eval

Formatting runs first so that every diagnostic range points into the exact text that is stored and that the agent will edit. If the code does not parse, it is stored as written and the syntax error is reported.

The design

Five parts

1

An async admit chain in the interpreter

It joins SessionHooks next to the other chains that run before evaluation. runStep calls it after response and before evaluateStep. The base case returns the code unchanged with no diagnostics.

readonly admit: Chain<[ctx: StepContext], Promise<Admission>>;

type Admission = { code: string; diagnostics: Diagnostic[] };
  • Any error-severity diagnostic skips eval and pushes a tool entry with source: "lisp-check". The loop continues, so the model reads the errors as its next input.
  • Otherwise admission.code replaces code for the rest of the step, the assistant wire event included. That makes the formatted text what lands in messages.content.
  • The agent loop never learns which extension rejected the step, so the seam holds.
2

A lint extension that owns the checker

For example packages/lint, @repo/lint-extension. The name checks is already the eval DSL.

  • Move the checker out of the LSP. tokenize.ts and call-diagnostics.ts return a neutral {range, message, severity, code}. apps/lsp and the MCP lisp-check import it at their own composition roots. Editor and agent share one checker.
  • Strip prose through the seam. Run the interpreter's readSource chain instead of importing formsOnly, so lint never names the prose extension.
  • Undefined symbols. Lexical scope over let, lambda, defun parameters and the other binding forms. Known names are globalNames() plus whatever the same submission defines. Macro call arguments are skipped, since expanding a user macro runs code. Error in a top-level call, warning inside a function body.
  • Types, later. Check literal arguments against the declared argument type only. Inference is its own project.
3

Formatting through a host port

A subprocess is an outward reach, so the extension declares FormatHost and is handed an implementation. The app spawns ptcfmt, which means its image carries the Topiary binary and the compiled grammar from nix build .#ptcfmt. A TypeScript printer would avoid that, at the cost of two formatters that drift.

interface FormatHost {
  format(text: string): Promise<string | null>;
}
4

Recovery by editing, then by rewriting

The extension sets a rejected REPL variable to the last rejected source, the same way setConversationVars sets the conversation. It adds revise: a strict replace that fails on zero or several matches, checks the result the same way, and evaluates only when it is clean. A rewrite is just a new step.

step 1 · agent 
(defun total (items)
  (reduce + 0 items))

(echo (totl prices))
step 1 · lisp-check, not run 
line 4: "totl" is not defined.
  did you mean total?
fix: (revise :old … :new …)
  on rejected; rewrite only if
  an edit cannot express it
step 2 · agent 
(revise :old "(totl prices)"
        :new "(total prices)")

"Edit first" lives in the extension's prompt and in each rejection message. An eval case in apps/trace-viewer/evals asserts the agent reaches for revise before rewriting, so the rule is held by a test. The existing step cap stops a model that keeps hitting the same error.

Two decisions before building

Undefined heads versus prose

Today a form whose head does not resolve becomes prose. A static "not defined" error flips that: a typo becomes an error instead of being dropped. That is likely the goal, but the prose extension's failedForm behaviour and its tests change with it.

Code the user types

evalUserCode in apps/app/server/agent/chat.ts:166 could pass through admit too. That is consistent, and the user then sees the same diagnostics in the UI.

Order of work

Each step ships on its own

  1. Move the checker into the lint extension and switch apps/lsp to it. Nothing changes for the agent yet.
  2. Add the admit chain, its call in turn.ts, and the rejection result.
  3. Add revise, rejected, the prompt, and the eval case.
  4. Add the format port and ptcfmt in the app image.
  5. Add the undefined-symbol check, then the literal type checks.
