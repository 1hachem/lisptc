Per extension

The bundles

Each extension declares one <Name>Host with a field per port, and takes it as its first argument. The default arrives as a default argument, so the common call is unchanged and a swap is one spread away.

Keeping it

What stops the drift

The repo keeps constraints in code, not prose. Three things fail when the boundary is crossed again.

pnpm check:arch

Fails CI and the pre-push hook when an extension module imports a node builtin, a typed env module, an SDK or dotenv, or reads process.env — and names the -host.ts to move it to. Type-only imports stay allowed.

host-ports.test.ts

Asserts behaviourally that a supplied port is the one the extension uses, and that every default still resolves to its colocated .ptc.

The pattern is written where agents working in this repo read it, so a new extension follows it by default rather than by review.

packages/interpreter/src/extensions/prose/prose.ts imports a node builtin (node:fs) An extension defines the interface; the host lives in its colocated -host.ts and arrives as the default argument. Move it to packages/interpreter/src/extensions/prose/prose-host.ts.

The shared vocabulary — Clock, PromptSource, systemClock — lives in @repo/shared/host, the runtime-free half that extensions may import. @repo/shared/host-node holds filePrompt and the only node:fs in the pair, so check:arch gets the boundary for free.
