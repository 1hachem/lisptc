§1

The memory extension

An agent that works something out in one session loses it by the next. The memory extension gives the interpreter a store that outlives it, addressed by key, retrieved by regular expression, and fired by the shape of what the agent is doing right now.

What a memory is

One record, seven fields. The body is the interesting one: it holds prose or a form, because in this dialect those are the same material.

key
string
The address. Also the filename on disk, sanitized.
body
unknown
Prose to load into context, or a quoted form to replay. A live value (closure, promise, secret) is refused: it prints as #<…> and would not read back.
on
Trigger?
A kind and an optional pattern. Absent means the memory only ever arrives through an explicit recall.
links
Map<string, number>
Weighted edges to other keys. At weight ≥ 2 a link fires the memory it points at.
score
number
Strength at lastUsed. Decays from there.
used
number
Retrieval count.
lastUsed
number
Epoch ms. The exponent in the decay.

The six forms

The verbs are slashed because remember, recall and forget are ordinary English, and a bare one in an aside would be read as code. memories is not, so it stays bare.

Triggers: a memory that fires by itself

With :on the memory watches for an event and loads itself when it happens, unasked. Seven kinds, and the split that matters is one structural, six textual.

KindFires onPattern is
calla form about to be evaluated, at any deptha form, matched structurally
resultthe printed value a form returneda string, used as a regular expression over the text
erroran evaluation that raised
stepevery step, pattern or not
prosethe words around the forms, recovered by diffing the source against stripProse
userthe newest entry in the user-messages global, once per new message
recallanother memory being retrieved — retrieval is itself an event

Handing a string to call, or a form to any of the others, is a parse error with the correction in it. That check is what makes the shape distinction survive contact with a model.

Firing, cascading, wiring

A fired memory is REPL feedback, not a program. Nothing is evaluated. The line key: body goes to the model and, on the memory channel, to whatever front-end is listening. To run a memory you replay it; to show the user one you echo it.

Each memory fires at most once per step. A fired set guards it, so a cycle in the link graph terminates. Cascades stop at depth 3.

Retrieval is an event, so a memory hooked (recall "other-key") arrives alongside the one that was actually asked for. :links says the same thing outright.

What fires together gets wired together. At the end of the step, wireTogether() increments a link between every pair that fired. Links reach the firing threshold on their second co-occurrence, so the things the agent keeps using together start arriving together without anyone declaring it.

Strength, decay, and the sweep

Strength is score halved every week since last use: score · 2^(−elapsed / HALF_LIFE). Recall reinforces by re-basing the score on the decayed value and adding a constant, so a memory climbs only while it is being used faster than it fades. Left alone between recalls, each retrieval pays down the decay before it adds anything.

ConstantValueEffect
INITIAL_SCORE1every memory starts level
REINFORCEMENT0.5added to the decayed strength on each retrieval
HALF_LIFE_MS7 daysunused, a memory halves every week
FORGET_BELOW0.05swept from the store on the next step or recall — roughly four weeks of neglect from a fresh memory
MAX_CASCADE_DEPTH3how far a chain of links and recall-triggers can run
LINKED_FIRES_AT2link weight at which a link starts firing; an explicit :links is born at this weight
MAX_RECALL_WORDS200context budget for one step's recalled text

The budget is a hard cut, not a truncation: once 200 words are spent, further bodies are counted and dropped, and the step ends with a line saying how many words were withheld and how to get at them.

The plasticity window

Retrieving a memory puts its key in an open set that the end of the step clears. revise only works on an open memory; outside the window it raises an error telling you to recall it first. Reading and rewriting are deliberately one act — a memory gets corrected while its wrong text is on screen.

The store, and the layering

MemoryStore is four methods: all, get, put, delete. Three implementations ship.

ImplementationBackingUsed by
VolatileStorea Maptests, and anything that must not touch the real store
FileMemoryStoreone .ptc s-expression per memory, dir 0700, files 0600the CLI, the MCP server, the session server
LayeredStorean own store over a shared one: reads fall through, writes land in own, deletes hit boththe API, via scopedMemoryStore(distinctId)

Persistence is the printer and the reader, nothing else — a memory on disk is a form this language can read, which is also why a trigger that no longer parses is kept rather than dropped.

Scope is the person, not the thread. The API derives the scope from distinctId, so a REPL rebuilt for a new thread keeps the same memories, and two people on the same deployment share the base layer while writing only into their own.
§2

What it does to the interpreter

Nothing in lisp.ts knows about memory. The extension is a function of an Interp that installs itself through three existing seams, and carries two things the hosts read back off it.

The three seams

1 · The eval hook. interp.hooks.evalForm.use wraps every form evaluation, so the bank sees the call going in and the value or the exception coming out. That single wrapper is where four of the seven trigger kinds are sourced. It also means a form evaluated inside a replay or a function body still passes through — the step guard, not the hook, is what keeps those from firing.

2 · Definitions. Six interp.def / defGen calls, each with its signature, doc string and zod argument schema, so the six forms show up in (doc), in the language reference the system prompt carries, and in the LSP's completions for free.

3 · Channels. bank.attach(interp.channels). Every fired memory is emitted on MEMORY as well as folded into the step's text.

The step boundary lives in the host

This is the part that is not an interpreter concern at all. Interp has no notion of a step; it evaluates forms. The bank needs one, because "fires at most once per step", "the revision window", "the recall budget" and "wire together what fired together" are all step-scoped. So the extension exposes beginStep(code, interp) and endStep(), and each host calls them around its own idea of a step:

HostCallsDoes what with the returned text
packages/repl · MemoryReplbeginStep / endStep
around runAsync		collects fired memories off the channel into EvalOutput.memories
packages/repl · InteractiveReplbeginStep / endStep
around the line		write()s it straight to the terminal
packages/ai · AgentReplinherits MemoryReplhands memories to the turn loop, which attaches them to the step's meta

Outside a step, dispatch returns immediately. That is what stops the prelude — hundreds of forms evaluated at construction — from firing every step-triggered memory in the store.

What else it touches

  • The system prompt. memory.ptc ships beside the source, is read at module load, and rides on the extension's prompt. Interp collects those into systemPrompt(), appended after the language reference — so the agent learns the six forms from the same place it learns car.
  • Compaction. memory/recall and memories joined READ_FORMS, the set of calls whose output the compactor treats as a read rather than a result worth keeping whole.
  • A global it reads, and does not define. The user trigger reads user-messages, which the agent loop refreshes before every step. In the bare CLI that global does not exist, and the trigger simply never fires.
  • Env. One new module, @repo/env/memory, declaring LISPTC_MEMORY_DIR and XDG_CONFIG_HOME.
The discovery pattern. bankOf(extension) joins compactorOf and storeOf: the REPL walks its extension list asking each one what it carries, instead of being told which extensions it has. Adding a capability to a host is adding one entry to an array.
§3

Channels, end to end

One evaluation produces several streams of text with different audiences. Channels are how the interpreter emits all of them without deciding who reads what.

Every emit goes to the named channel and to "*". A listener that throws is swallowed, so a broken front-end cannot take down an evaluation. Subscription returns its own unsubscribe, which is what lets the REPL listen for exactly the length of one eval.

user
Written by echo, doc, the compactor.
Read by the human. This is the only channel a person is meant to see verbatim.
model
Written by doc, the compactor's step report, and every EvalException that escapes a top-level form, with severity: critical.
Read by the agent, as tool-result text.
memory
Written by MemoryBank.say, once per fired memory, carrying {key, body} in value.
Read by the REPL, which turns it into a structured list rather than more text.
debug
Declared, nothing emits on it yet. The name is reserved for tracing that should never reach either audience.

Severity is the second axis, and the REPL uses it to split one channel three ways: a warning on the model channel is a skipped form, collected into a skipped list; a critical is an error already handled by the catch; anything unmarked is output.

The path a fired memory takes

§4

Ports we could cut

The same shape keeps recurring: an extension owns a language surface and a prompt, and delegates the part that touches the world to an interface it takes in its constructor. Where that interface exists, hosting is a swap. Where it does not, the decision is baked into a module-level constant.

MemoryStore

exists
Today
Volatile, File, and Layered; scopedMemoryStore(scope) composes the last two. The clock is injected too, which is what makes the decay testable.
Strain
Retrieval is all().filter().sort(). That is fine for a directory of files and wrong for anything remote, which would have to page the whole store over the wire on every step. A durable adapter wants the port to grow search(query, limit) and let the backend answer it.
Unlocks
Postgres or SQLite for a hosted deployment; an embedding index behind the same four methods; a read-only org layer under the person's own, which LayeredStore already composes for free.

SecretsStore

exists
Today
The interface is get, list, set; the one adapter scans REPL_* out of the environment, with a dotenv loader beside it. secretsExtension({ store }) already takes an injection, and the eval harness passes its own.
Strain
No scoping. Memory grew a scope and a layer this branch; secrets have neither, so a hosted deployment has one flat namespace of secrets shared by everyone on it.
Unlocks
A scopedSecretsStore(scope) mirroring the memory one, over a vault adapter — the repo already has a setup-infisical branch — plus per-org defaults under per-user overrides in the same LayeredStore shape.

McpClient

exists
Today
Six methods — connect, callTool, disconnect, login, logout, authorize — and mcpExtension({ client }) takes one. The evals already substitute a mocked client, which is proof the seam holds.
Strain
The one adapter does two unrelated jobs: speaking MCP, and deciding where the server runs.

McpHost — where a server runs

not cut yet
Today
Inside mcp-client.ts: spawn with detached: true, keep the last 4KB of stderr, poll a localhost URL with HEAD every 250ms for up to 60 seconds, and keep a module-level Map of children that stopLocalServers() kills. Every deployment of the agent therefore runs its MCP servers as child processes of the API.
Shape
ensure(conf) → { url, headers }, stop(name), status(name), logs(name). The client stops caring whether a URL is a subprocess it started or a container someone else owns.
Unlocks
A container per tenant instead of a subprocess per API instance; a server that outlives the request that started it; per-user isolation for a stdio server that reads the filesystem; a hosted deployment where the API has no business spawning npx at all.

ToolkitRegistry — which servers exist

not cut yet
Today
readFileSync of a bundled mcp.toolkit.json, ${VAR} expansion against the real environment, relative paths resolved against the bundle. registerMcp takes a toolkitJson string override, which is a seam for tests but not for a catalog.
Shape
list(), search(query), get(name) — the three things (list-toolkit), (search-mcps) and (load-mcp name) actually ask for, returning configs rather than a file's contents.
Unlocks
A catalog fetched at runtime; per-org server lists; a server a user added themselves; ranking by what this person has actually loaded before.

OAuthStore

interface, not a seam
Today
The interface exists and FileOAuthStore implements it — then mcp-client.ts pins it with a module-level const oauthStore = new FileOAuthStore(). Tokens land on the disk of whatever machine happens to run the API, which also means a second instance cannot see the authorization the first one captured.
Shape
Already right. It needs to arrive through mcpExtension like the client does, and to be keyed by scope so two people's Google accounts do not collide.

SessionStore — the live REPL

not cut yet
Today
A module-level Map<threadId, AgentRepl> capped at 50, evicting oldest-first. A restart drops every definition the agent built; a second API instance is a different set of sessions.
Shape
get(threadId, scope), evict(threadId) — and the harder half, a rebuild path, since what makes a session is the forms that were evaluated into it.
Unlocks
Sticky sessions across instances, and an honest answer to what survives a deploy. Memory already answers it one way: definitions die with the interpreter and memories do not, which is exactly why a recipe worth keeping belongs in a memory rather than a defun.

Channels as a sink

already the seam
Today
Telemetry is called explicitly from the turn loop — captureReplEval, captureLlmCall, captureTurn — while the channels carry a strictly richer stream that nothing subscribes to wholesale.
Shape
No new interface. channels.on("*", sink) is the port; what is missing is an adapter that ships Diagnostics to a trace, and a debug channel that has something on it.
The through-line. Four of these are the same refactor: take a decision currently frozen in a module-level constant, name it as an interface, and pass it in where the extension is constructed. The memory extension is the worked example — the bank takes a store and a clock, the store composes, and the scope comes from the caller — and it is the one that made the missing seams elsewhere visible.
