Five patterns govern this repo, and four of them are good. The one that fails fails in a specific way: coupling forbidden to move sideways moves down instead, into the two layers that have no rules — @repo/interpreter and @repo/shared. And the agent's working memory lives in a 50-entry Map that dies with the process.

;; part one

The patterns, and what each one buys

Read in dependency order, bottom to top. Each verdict is about load-bearing capacity, not taste: holds means it will still be true at ten extensions, strains means it works but the cost grows with use, breaks means it is already wrong today.

P1

Layering declared as tags, not described in prose

holds

Every package carries a turbo.json naming one tag. The root declares which tag may not depend on which, and pnpm boundaries fails the build on a wrong-direction edge. The rule that matters most is one line: extension denies extension. No extension can ever name a sibling.

turbo.json — boundaries.tags 
"extension": { "dependencies": { "deny": ["extension", "runtime", "frontend", "product"] } },
"language":  { "dependencies": { "deny": ["extension", "runtime", "frontend", "product"] } },
"runtime":   { "dependencies": { "deny": ["extension", "backend", "frontend", "product"] } },
// foundation (@repo/shared, @repo/env) denies everything above it.
// Nothing denies depending ON foundation. That asymmetry is P1's blind spot.
Why it works

The constraint lives where the dependency is declared. A reviewer never adjudicates layering; CI does, and the failure names the way out.

Why it works

Nine extension packages, zero edges between them. Verified, not asserted.

What it costs

Tags constrain direction, never content. Any package may depend on foundation, so any fact placed there becomes legal for everyone to share. See finding 2.

What it costs

Turbo does not detect circular imports between files inside a package. The interpreter's internal stack ordering is doctrine, not a check.

P2

Host ports — the extension declares, the root provides

holds

Everything reaching outside the process goes through an interface the extension declares itself, in <name>.ts. The implementations sit in <name>-host.ts, which the extension file never imports. There is no default host, so a composition root is the only place a concrete implementation is named.

packages/memory/src/ports.ts:43 
export interface MemoryStore {
  all(): Awaitable<Memory[]>;            // value or promise: both satisfy it
  get(key: string): Awaitable<Memory | undefined>;
  put(memory: Memory): Awaitable<void>;
  delete(key: string): Awaitable<boolean>;
}
export interface MemoryHost { store: MemoryStore; clock: Clock; prompt: PromptSource; }

The Awaitable<T> return is the subtle part. A file-backed store answers synchronously, a Convex-backed store answers with a promise, and the evaluator consumes both through its own suspension rather than through async. The port does not force every caller to become asynchronous just because one implementation is.

Why it works

Ports are small. Five of eight extensions declare a host of exactly one field, prompt. A small port is a port people keep honest.

Why it works

Test doubles are free. Swapping DockerHost for LocalProcessHost is a composition-root edit, not a code change.

What it costs

McpClient has grown to seven async methods including login, logout and authorize. OAuth ceremony has leaked into what should be a transport port.

What it costs

The enforcement is a hand-maintained path list, not the tag. See finding 3.

P3

The session seam — chain, slot, annotation

strains

Three kinds of thing cross the seam and each has exactly one mechanism. Behaviour is a Chain an extension hooks. A capability is a Slot it fills. Data is an annotation it attaches. Nothing above an extension names it; the driver runs chains and carries bytes without knowing who produced them.

packages/interpreter/src/session.ts:50 & hooks.ts:16 
export interface Slot<T> { readonly name: string; readonly held?: T; }
export function slot<T>(name: string): Slot<T> { return { name }; }

run(base: (...a: A) => R, ...args: A): R {
  let next = base;
  for (let i = this.middlewares.length - 1; i >= 0; i--) {
    const middleware = this.middlewares[i];
    const rest = next;
    next = (...a: A) => middleware(...a, rest);
  }
  return next(...args);            // first registered runs OUTERMOST
}

The whole mechanism is about forty lines and the slot is a bare string key. That economy is the pattern's strength and its exposure: fill is last-write-wins with no arity check, and filled returns undefined when nobody filled it. A missing capability is not a build error, it is a runtime undefined.

Why it works

The agent loop genuinely does not name an extension. mergeInto spreads annotation keys it never reads, all the way to the wire.

Why it works

One verb each way, emit and collect. A vocabulary that small is enforceable in review.

What it costs

Only four of eight extensions hook a chain at all, and where two share one, array index decides who wraps whom. See finding 4.

What it costs

A slot placed in the core turns the seam into a public channel between any two layers. See finding 2 — this is how the one real breach happened.

P4

The evaluator is a generator, so suspension is not contagious

holds

The best decision in the repository, and the least documented. Eval<T> is a generator that yields promises. A form that must wait yields; a driver decides what waiting means. Two drivers over one evaluator.

packages/interpreter/src/drive.ts:5 
export type Eval<T = unknown> = Generator<Promise<unknown>, T, unknown>;

export function driveSync<T>(gen: Eval<T>): T {
  let step = gen.next();
  while (!step.done)
    step = gen.throw(new EvalException("cannot suspend",
      "this host evaluates synchronously", false));   // LSP, static checks
  return step.value;
}

This is why the LSP can complete against a live session without an event loop, and why the agent can await an MCP tool call mid-form. Colouring is decided at the edge instead of infecting every signature underneath. Most interpreters that bolt on async end up with two evaluators.

Why it works

One evaluator, two execution disciplines. The sync driver turns suspension into a language-level error with a real message rather than a hang.

Why it works

It composes with P2: an Awaitable port is consumable from inside the evaluator without async creeping upward.

What it costs

Every frame is a generator frame. That is a real constant-factor tax on a tree-walker, and no benchmark in the repo pins it.

What it costs

The trampoline in evalGen is a 120-line for(;;) with an eight-case keyword switch. It is the single most-edited file in the repo (47 touches).

P5

Persist the source, never the closure

holds

A memory stores a printed s-expression. Anything holding a live value is refused at save time, by checking whether the printed form contains the unreadable markers. Restore is readForm plus, if you want the effect, evaluation.

packages/memory/src/memory.ts:58, :461, :583 
function unreadable(body: unknown): boolean {
  const printed = str(body);
  return printed.includes("#<") || printed.includes("#:");
}

if (unreadable(body))
  throw new EvalException(
    "a memory body must be prose or a form that reads back; this one holds a live value", body);

// memory/replay: a memory holding a `defun` installs that function when you replay it
return yield* interp.evalGen(memory.body, null);

This is exactly right, and it is the pattern that finding 1 says to extend. Serialising a closure is a trap every Lisp-in-a-database eventually falls into; refusing at the boundary with a message that tells the model what to do instead is the mature answer.

Why it works

The durable artifact is text a human can read, diff and repair. No schema migration for the value graph, ever.

Why it works

Bounded on purpose: 500 memories, 32 KB each, enforced in the mutation rather than hoped for.

What it costs

Only explicit memories get this treatment. The session's own bindings get nothing. That asymmetry is finding 1.

What it costs

unreadable is a substring test on printed output. A string containing "#<" is rejected as a live value.

Where the patterns stop working

Ranked by what they cost at the next order of magnitude, not by how wrong they look. Each carries the code that proves it and the pattern I would replace it with.

01

The agent's working memory is a cache that thinks it is a database

apps/api/src/repls.ts:6 · packages/ai/src/repl-store.ts:4 · packages/repl/src/repl.ts:99

The README calls the Lisp runtime the side that "holds memory". It holds it in a module-level Map, capped at fifty threads, in one process.

// apps/api/src/repls.ts:6 — one Map, for every thread, for the life of the pod
export const repls = new ReplStore(chatRepls(() => convexAs(currentSession())));

// packages/ai/src/repl-store.ts:4
const MAX_THREADS = 50;
private keep(threadId: Id, repl: AgentRepl): void {
  while (this.repls.size > this.max) {
    const oldest = this.repls.keys().next().value;
    this.repls.delete(oldest);          // no flush, no warning, no trace
  }
}

// packages/repl/src/repl.ts:99 — what a reopened thread gets back
private freshInterp(): Interp {
  const interp = new Interp({ extensions: this.extensions });
  runSync(interp, prelude);
  this.setup(interp);     // AgentRepl.setup restores conversationVars. Nothing else.
  return interp;
}

So every define, defun and defmacro the agent wrote is lost on deploy, on the 51st concurrent thread, or on any request that lands on a second instance — while the transcript in Convex still describes them in detail. The model is handed a history asserting a vocabulary its environment no longer has. This also means apps/api cannot be horizontally scaled today: a second replica is not a slower path to the same answer, it is a different and wrong one.

The memory extension does not close this. It persists what the agent deliberately remembers, keyed by workspace, never the session's own bindings, and nothing replays memories into a fresh environment at open.

Suggested pattern

Event-sourced session: the environment is a fold over a durable definition log

Do for the session exactly what P5 already does for memories. A REPL environment is not a value graph worth serialising, it is the result of replaying forms in order. Append every accepted top-level definition to a durable log keyed by thread; make opening a REPL a fold over that log.

// a port on the runtime, not an extension — the REPL already owns thread identity
export interface SessionLog {
  append(threadId: string, step: number, form: string): Awaitable<void>;
  since(threadId: string, step: number): Awaitable<{ step: number; form: string }[]>;
}

// ReplStore.open becomes: build empty, then replay.
const repl = new AgentRepl({ extensions });
for (const { form } of await log.since(threadId, 0))
  await repl.evaluate(form);              // same path a live step takes

Why it is better. It makes the LRU a real cache — correct to evict at any moment, for any reason — instead of the system of record. That single change buys horizontal scaling, safe deploys, and a bounded memory footprint, none of which are available now. It reuses a decision the repo has already made and already trusts, so there is no new concept to teach the model: a remembered defun and a logged defun replay through the same evaluator.

What to log. Not every step — effectful forms must not re-fire on replay. The seam already knows which ones those are, so add one chain rather than a heuristic:

// packages/interpreter/src/session.ts — a new chain beside the others
readonly replayable: Chain<[form: unknown], boolean>;
// base returns true. mcp, llm and promises hook it and return false for their own forms.
// An extension that reaches the world already knows its forms are not pure. Ask it.

The invariant, in code, where the doctrine says it belongs. A test that evicts a thread, reopens it, and asserts every symbol the log defined still resolves. Today nothing fails when this breaks, which is why it is broken.

If the full log is too much for a first move, log only top-level definition forms. It is bounded, it is the 95% case, and it turns a silent correctness bug into a capacity question.

02

The seam is drawn but the abstraction is not interfaced — coupling sinks to the basement

packages/interpreter/src/observe.ts · packages/shared/src/providers.ts · packages/ai/src/turn.ts:127

This is the answer to the question you asked. The rules forbid coupling from moving sideways (extension denies extension) and from moving up (runtime denies extension). They say nothing about moving down. So it moves down, into the two packages everyone is allowed to depend on and neither of which has content rules.

Basement one, the core. @repo/interpreter "ships no extension and names none". It names one:

// packages/interpreter/src/observe.ts — inside the package that names no extension
export interface LlmCall {
  builtin: string; provider?: string; model?: string;
  messages: ChatMessage[]; structured: boolean; latencyMs: number;
  output?: string; inputTokens?: number; outputTokens?: number; error?: string;
}
export const llmSlot = slot<Observed>("llm");

// packages/ai/src/turn.ts:127 — the tree that "may import no extension module at all"
const observed = repl.hooks.filled(llmSlot);

Letter honoured, spirit gone. packages/ai never writes @repo/llm-extension, so check:arch is satisfied — yet it knows a model exists, knows a call has a provider and a token count, and telemetry.ts imports LlmCall to interpret it. Compare the two slots that were done right: memorySlot and secretsSlot each live in their own extension package.

And check:arch is structurally blind to it. isExtensionModule() returns false for every path under packages/interpreter/src/, so the BLIND rule that guards packages/ai/src cannot see through a core re-export. Turbo agrees: runtime is allowed to depend on language. Moving a contract into the core is the sanctioned-looking way to couple any two layers.

Basement two, the foundation. @repo/shared is the no-dependency utility layer that thirteen packages import. It decides which models exist:

// packages/shared/src/providers.ts — in the layer below the interpreter
export interface ProviderSpec {
  label: string; apiKey: string | undefined;   // a secret, beside a whole secrets extension
  apiKeyEnv: string; baseUrl: string; defaultModel: string;
}
export const PROVIDER_NAMES = ["digitalocean", "fireworks", "openrouter"] as const;
export const DEFAULT_PROVIDER: ProviderName = "openrouter";

The doctrine says no extension decides "which model answers". Correct — instead the foundation decides, for everyone, as a closed union. Adding a provider edits the package with the largest blast radius in the repo and invalidates every downstream Turbo cache entry, to change the most volatile fact in the system. @repo/shared also carries lisp-prose.ts, a 400-character regex that is the prose extension's core discriminator, sitting two layers below the extension that owns it.

Suggested pattern

Demote the contract to data: an annotation, not a slot in the core

The repo's own written rule already prescribes the fix — "a payload a layer above would have to interpret belongs below the seam instead: move the interpretation into the extension." An LLM call record is data. It should cross as an annotation on a topic the LLM extension declares, collected by the driver like every other report, and observe.ts should be deleted.

// in packages/llm — the extension owns the shape AND the interpretation
const llmCalls = topic<TelemetryEvent>("llm-call");

session(hooks) {
  hooks.annotate.use((buffer, into, next) =>
    next(buffer, annotating(into, "step", { telemetry: buffer.take(llmCalls) })));
}

// packages/ai/src/turn.ts — unchanged, because it already forwards keys it never reads
// mergeInto(lastMeta, event.annotations.step)

Why it is better. It removes an import edge instead of legalising one, and it costs nothing to build because mergeInto already spreads unknown keys to the wire. The test that today asserts filled(llmSlot) becomes a test that a telemetry annotation arrived — which is the thing you actually care about, and which stays true if the LLM extension is swapped out.

For the foundation leak, invert the ownership: ProviderSpec is a host concern, so build it at the composition root and hand it in through LlmHost. At the port boundary a provider is a string the host validates, not a union the foundation closes. Adding a provider then touches one root and rebuilds one package.

And close the hole generally, because the next contract will want the same basement. Two rules, both cheap, both in check:arch:

  • No slot<T>(...) may be declared under packages/interpreter/src/. The core defines the mechanism; only an extension mints a key.
  • A module under packages/shared/src/ may not be imported by more than one tag family — or more bluntly, keep a written list of what shared is allowed to contain and fail on additions. A layer with no rules and universal reach will collect whatever the rules elsewhere squeeze out.
03

The architecture check is enforced by hand-maintained path lists

scripts/check-arch.ts:64–77, :113–119

Every rule that guards the port pattern hangs off two literal arrays. They already do not cover the repo:

const EXTENSION_DIRS = [
  "packages/compaction/src/", "packages/memory/src/", "packages/promises/src/",
  "packages/prose/src/", "packages/secrets/src/", "packages/ui-extension/src/",
];
const EXTENSION_FILES = [
  "packages/llm/src/llm.ts", "packages/mcp/src/mcp.ts", "packages/mcp/src/ports.ts",
];

function isExtensionModule(file: string): boolean {
  if (file.endsWith("-host.ts")) return false;
  if (EXTENSION_FILES.includes(file)) return true;
  return EXTENSION_DIRS.some((dir) => file.startsWith(dir));
}
  • packages/checks is tagged extension and appears in neither list. It is entirely unchecked.
  • packages/llm/src/llm-client.ts and langchain.ts are unchecked, which is why llm-client.ts reads @repo/env without failing anything.
  • Every packages/mcp/src/*.ts beyond the two named files is unchecked.
  • A tenth extension package will be silently exempt until someone remembers this file exists.

The same shape repeats in SNIFFER, the rule meant to catch a function digging a field out of an extension: /export function (\w+)\([^)]*: InterpExtension[,)]/. An arrow function, a class method, a second parameter, or a type alias all walk straight past it.

Suggested pattern

Derive the rule from the declaration that already exists

Every package already declares what it is, in its own turbo.json. The checker should read that instead of a parallel list that has to be remembered.

function isExtensionModule(file: string): boolean {
  if (file.endsWith("-host.ts")) return false;
  const pkg = owningPackage(file);
  if (tagOf(pkg) !== "extension") return false;
  return !hostModulesOf(pkg).includes(file);   // opt-out declared in the package's own turbo.json
}

Why it is better. New extensions are covered by default instead of by memory, and the exemption for a file like llm-client.ts moves next to the code it exempts, where a reviewer touching that package will see it. This is the repo's own "make the wrong thing unrepresentable" principle applied to its own tooling — the list that can silently drift out of date stops existing.

For SNIFFER, use the TypeScript compiler API. It is already a dependency: check-comments.ts uses ts.getLeadingCommentRanges. Parsing for one check and regexing for the rest is a choice, not a constraint.

04

Nine hand-kept rosters, and the one the evals run is not the one that ships

packages/backend/src/agent-repl.ts · apps/cli · apps/lsp · apps/trace-viewer/evals

Only four of the eight extensions hook a chain at all. secrets, promises, mcp and llm register builtins and fill slots; they never touch the lifecycle. So the seam's chain machinery carries less traffic than its prominence suggests — and where two extensions do share a chain, their relative order silently decides who wraps whom:

// who hooks what — only these four participate in the lifecycle at all
compaction → evalStep, stepOutput, stepError
memory     → beginTurn, evalStep, annotate
ui         → invoke, annotate, message
prose      → unrun, answered

// collisions, decided purely by array index in the roster:
evalStep : compaction (5) wraps memory (6)
annotate : memory (6)    wraps ui (8)

The mechanism itself is pinned — hooks.test.ts:11 asserts "runs middlewares outermost-first, in registration order" — but no test pins the relative order of any two extensions. The generic law is tested; its two live applications are not.

The larger problem is that there are nine of these lists, maintained by hand, and they have already drifted apart:

rosternwhat it leaves out
backend/agent-repl · workspaceExtensions8— the only complete one
cli · cliExtensions / sessionExtensions7ui
lsp · sessionExtensions7ui
lsp · docExtensions4secrets, memory, prose, ui
backend/test · modelFacing6mcp, llm
evals · browsing / linear4secrets, llm, memory, ui — and mcp is mocked
evals · memory5secrets, llm, ui — and mcp is mocked

That last group is the sharp end. The eval suite — the thing that decides whether a change to agent behaviour is good — runs a composition that never ships. No secrets extension, so no redaction path is ever exercised against a real model. Four extensions instead of eight, so roughly half the prompt and none of the chain collisions above. Evals are measuring a different agent from the one users get.

Suggested pattern

One roster, varied by host — and declare position instead of encoding it in an index

These nine lists differ in two ways that deserve different treatment. Host choice is a real argument; membership and order are not.

// one roster, in @repo/backend, parameterised by what actually varies
export function agentExtensions(hosts: ExtensionHosts): InterpExtension[] { … }

cliExtensions()   = agentExtensions({ mcp: new DockerHost(),       secrets: { envFile: true } })
evalExtensions()  = agentExtensions({ mcp: mockedMcp(),            secrets: fixedSecrets() })
// membership and order are now impossible to vary by accident.

// and for the collisions, let the extension state where it belongs:
export interface InterpExtension extends Installable {
  readonly session?: (hooks: SessionHooks) => void;
  readonly rank?: number;            // openSession sorts; array index stops being semantics
}

Why it is better. A roster becomes a set plus a host bundle, so the nine lists can no longer disagree about who is present — which is the drift that currently makes the evals unrepresentative. And rank turns wrapping order into a field the extension owns, which is the seam's own philosophy applied one level up: the extension declares, the driver arranges. An ordering constraint that lives in a field can be asserted; one that lives in an array index can only be remembered.

The cheap first move, before any refactor: make the eval roster call the same function the backend calls, with mocked hosts. That single change is what makes an eval result mean something about production.

05

Prompt cost scales linearly with installed extensions, and is fixed at construction

packages/shared/src/host.ts:3 · every *.ptc

Each extension ships a prompt. All of them are concatenated into every turn, whether or not the turn touches them. Measured on the backend roster:

Roughly 13–14k tokens of language reference on every turn of every conversation. The extension whose entire purpose is bounding context, compaction, has the largest prompt after the core. And the port makes this structural rather than incidental:

export type PromptSource = () => string;      // packages/shared/src/host.ts:3

// every extension factory, e.g. packages/promises/src/promises.ts:48
return Object.assign((interp) => registerPromises(interp), {
  prompt: host.prompt(),        // called ONCE, at construction. A string, forever.
});

A prompt that is a string fixed at composition time cannot shrink for a turn that does not need it. This is the one cost in the system that grows with every extension you add, which is the thing the architecture is optimised to make easy.

Suggested pattern

Make the prompt a chain, like every other behaviour that crosses the seam

The seam's own rule is that behaviour crosses as a chain. Prompt assembly is behaviour. Nothing new needs inventing — beginTurn already proves the shape.

// packages/interpreter/src/session.ts
readonly describe: Chain<[ctx: TurnContext, into: string[]], string[]>;

// packages/mcp — contribute the full surface only when it is live
hooks.describe.use((ctx, into, next) =>
  next(ctx, connected.size === 0 ? [...into, mcpBrief] : [...into, mcpFull]));

Why it is better. It converts a fixed per-turn tax into one the extension controls, using a mechanism already in the file, and it keeps the layering intact — the driver still never knows who contributed what. An extension with nothing connected can cost two lines instead of six kilobytes. It also gives you the honest number: assert the assembled prompt size in a test, so a prompt that doubles fails CI rather than quietly costing money on every request.

Worth measuring before building: if prefix caching already covers the static block, the win is smaller than it looks, and the right first move is the assertion test rather than the chain.

06

The doctrine is drifting where nothing checks coverage

packages/*/AGENTS.md · README · scripts/check-refs.ts

"Every workspace carries an AGENTS.md of its own" is the root instruction and the entry point for working in a package. Six of the nine extensions do not have one — and they are exactly the six carved out of the interpreter on 2026-09-20, the newest and least understood packages in the repo:

MISSING  packages/compaction   packages/memory    packages/promises
MISSING  packages/prose        packages/secrets   packages/ui-extension

// also: apps/dashi-code, 5,389 LOC — the largest app — appears in neither
// the root CLAUDE.md package list nor the README layout.

check:docs allows an AGENTS.md anywhere but never requires one. check:refs validates that references resolve, not that packages are covered. Both checks guard against addition; neither guards against omission.

Suggested pattern

Make coverage a check, not a habit

// scripts/check-refs.ts — a few lines, same failure style as the rest
for (const pkg of workspaces()) {
  if (!exists(`${pkg}/AGENTS.md`)) fail(pkg, "every workspace carries an AGENTS.md");
  if (!readmeLists(pkg))           fail(pkg, "README names every workspace");
}

Why it is better. The repo's whole thesis is that a constraint worth keeping lives in code, not prose. This one is currently prose about prose, enforced by nobody, and it broke within seven days of the rule being written. That is a reasonable failure — it is also exactly the failure the thesis predicts, so fix it the way the thesis says.
